# 査察AI（防火対象物査察支援 v4.0・個人用版）

立入検査で見つけた指摘事項から根拠法令を引くための、個人用の検索・学習ツールです。
単一HTMLのPWAで、スマートフォンのホーム画面から起動でき、オフラインでも条文を閲覧できます。

リポジトリは現在 **private** で、GitHub Pages は未設定です。
公開すると `https://ancool2080-crypto.github.io/sasatsu-ai/` で使えるようになります（下記「公開する」参照）。

> **このツールは法解釈の最終判断を行うものではありません。**
> 提示される根拠法令は実務上の一般的な整理です。個々の事案への当てはめと最終的な判断は
> 利用者本人が、e-Gov法令検索および自治体公報の原典を確認したうえで行ってください。

---

## できること

| 機能 | 内容 |
|---|---|
| F1 指摘→根拠 | 指摘事項を自然文で入力すると、該当しうる根拠法令を条項レベルで提示します。用途区分（令別表第一）と延べ面積・収容人員も指定できます。 |
| F3 条文検索 | 語句でも条番号でも引けます（`誘導灯` / `令26条` / `法17の3の3` / `建基令112条`）。 |
| F2 査察メモ | 指摘と根拠法令を手元に蓄積し、横断検索できます。書き出し・読み込みに対応。 |
| F4 出力 | 検索結果やメモをブラウザの印刷機能でPDF化できます（出典URLも印字されます）。 |
| AI解説 | Claude APIキーを登録した場合のみ、平易な解説を追加します。未登録でも全機能がオフラインで動きます。 |

すべての条文に e-Gov法令検索への直リンク（条単位のアンカー付き）と、施行日・最終取得日が表示されます。

## 収録している法令

ビルド時に [e-Gov法令検索 法令API Version 2](https://laws.e-gov.go.jp/api/2/swagger-ui) から取得し、
静的JSONとして同梱しています。ブラウザから e-Gov へ直接アクセスはしません。

- 消防法（323AC1000000186）
- 消防法施行令（336CO0000000037）
- 消防法施行規則（336M50000008006）
- 建築基準法（325AC0000000201）
- 建築基準法施行令（325CO0000000338）
- 危険物の規制に関する政令（334CO0000000306）— 少量危険物・指定可燃物の判断に必要なため収録

**火災予防条例は e-Gov法令検索に収録されていません。** 各自治体の例規集から取得したものを、
自治体名をマスクしたうえで手動で投入します（下記）。

## 防火管理者の判定

用途区分（令別表第一）・収容人員・延べ面積から、選任義務の有無と甲種／乙種の別を根拠条文つきで返します。

| 根拠 | 内容 |
|---|---|
| 令第1条の2第3項第1号イ | （六）項ロ等 … 収容人員10人以上。面積にかかわらず**甲種** |
| 令第1条の2第3項第1号ロ | 特定用途 … 収容人員30人以上。延べ面積300㎡以上で甲種、未満は乙種可 |
| 令第1条の2第3項第1号ハ | 非特定用途 … 収容人員50人以上。延べ面積500㎡以上で甲種、未満は乙種可 |

収容人員は**自動計算しません**。用途を選ぶと規則第1条の3の表からその用途の算定方法を表示するので、
それに従って出した数を入力します。算定方法の解釈で結論が変わる部分を機械が勝手に決めないためです。

判定後は、選任・解任の届出、消防計画の作成・届出、（特定防火対象物なら）消火・避難訓練の年2回以上、
権原が分かれていれば統括防火管理者の要否を、根拠条文つきで併せて表示します。

## 設備判定

用途区分と延べ面積から、消火器具の必要能力単位と主要な消防用設備の設置義務に当たりを付けます。

**消火器具の能力単位は条文どおり計算します。**

```
（四）項 800㎡ 一般構造 → 基準面積100㎡（規則第6条第1項の表）→ 800÷100 = 8単位
（四）項 800㎡ 耐火＋内装難燃 → 2倍読み200㎡（規則第6条第2項）→ 800÷200 = 4単位
（七）項 250㎡ → 300㎡未満のため令第10条第1項第3号の設置義務に当たらない
```

電気設備がある場所（床面積÷100㎡・規則第6条第4項）、多量の火気を使用する場所（÷25㎡・同第5項）の
追加分も出します。収容人員は規則第1条の3の表から、その用途に適用される算定方法を表示します
（従業者数や客席数は図面から分からないため、現地で確認した数を使ってください）。

主要な設備（屋内消火栓・自動火災報知設備・避難器具・誘導灯・消防用水・連結送水管・排煙設備）は
**当たり付け**です。ただし書・緩和・特例・階ごとの基準は入っていないため、確定は必ず条文で行ってください。

### 図面からの読み取りについて

**図面の輪郭から面積を測る機能ではありません。** 読み取るのは図面に書かれている
面積表・寸法の「文字」です。輪郭のトレースによる自動計測は精度が出ず、面積を誤ると
能力単位も設備判定も連鎖して狂うため、実装していません。

読み取りには Claude APIキーが必要です。読み取った数値は編集できる形で表示し、
**確認してから**計算に反映します。キーが無くても面積を手で入力すれば計算はすべて使えます。

### 図面との突き合わせ

同じ読み取りで、**凡例（レジェンド）と、図面に描かれている設備の種類**も拾います。
これを「法令が要求する設備」と突き合わせて3つに分けます。

| 区分 | 意味 |
|---|---|
| 図面に見当たりません（要確認） | 当たり付けでは義務なのに、図面に描かれていない |
| 図面に描かれています | 義務があり、図面にもある |
| 義務と判定していないが図面にある | 任意設置か、階ごと・部分ごとの基準による設置 |

**個数は参考値として表示するだけで、判定には一切使いません。** 撮影した図面では小さな記号を
数え漏らしたり重複して数えたりするため、個数を判定に使うと誤指摘や見逃しにつながります。
種類（描かれているかどうか）は比較的確実なので、そこまでを判定に使う設計にしています。

図面の範囲外（別図・別階）に描かれていることもあるので、「見当たりません」は
**現地確認の項目出し**として使ってください。

送信前に画像そのものを表示して確認を求めます。図面には社名・住所・設計者名が
写り込んでいることが多いためです（消防法第4条第4項）。

## ノウハウノート

査察マスターや建築消防adviceのような実務書で調べたことを、**自分の言葉で**残す場所です。
書いたノートは条文検索と「指摘→根拠」の結果にも出るので、次に同じ場面で迷ったときに自分の整理が先に見つかります。

```
見出し／分野／内容／関係する条文／出典メモ（何で調べたか）／タグ
```

**市販の書籍や解説書の文章をそのまま書き写さないでください。** 法令や通達と違い、
これらは著作権のある著作物です。要点を自分の言葉で整理したものを残す使い方を想定しています。

ノートは **localStorage にのみ保存され、リポジトリには入りません**。
査察メモと同じ注意喚起（自治体名・法人名・所属固有の運用の検知）が働きます。

## 執行手続きの参照

立入検査8段階・違反処理10段階を、各段階の根拠条文と標準マニュアルの該当ページに紐づけて表示します。
聴聞と弁明の機会の付与の区分など、行政手続法側の根拠も引けるよう**行政手続法・行政代執行法**を収録しています。

マニュアルのページ番号は**固定していません**。段階ごとの検索語で毎回本文を検索して解決するので、
マニュアルが改訂されて `fetch_fdma.py` を回し直しても、リンク先が自動で追従します。

## 消防庁の通知・標準マニュアル

出典：[消防庁ホームページ](https://www.fdma.go.jp/)。公共データ利用規約（PDL1.0）に基づき、
出典と加工を明示して利用しています。通知・通達は著作権法第13条第2号により著作権の目的となりません。

| 収録内容 | 状態 |
|---|---|
| 立入検査標準マニュアル | 全文92ページ（消防予第175号・令和5年3月16日改正） |
| 違反処理標準マニュアル | 全文156ページ（消防予第470号・令和7年10月16日改正） |
| 執務資料（質疑応答集） | 21件・本文64ページ。消防庁が出す質疑応答で、条文だけでは決まらない扱いが載る |
| ガイドライン | 8件・本文195ページ（関係者不在施設、大規模倉庫、直通階段が一つの建築物 ほか） |
| 予防関係の通知・通達 | 256件の書誌（番号・件名・日付・URL）。本文収録済みのものを除く |

執務資料とガイドラインは**件名のルールで自動選択**しています（`FULL_TEXT_RULES`）。
再実行すれば新しい執務資料が自動で入ります。

マニュアルは**ページ単位**で収録し、検索結果から原典PDFの該当ページへ直接飛びます
（`…pdf#page=47` の形式）。「聴聞 弁明の機会」で違反処理標準マニュアル P.22、
「用途判定 従属的な部分」で立入検査標準マニュアル P.20、といった引き方ができます。

```bash
pip install pdfplumber
python scripts/fetch_fdma.py              # 書誌＋マニュアル本文を取得
python scripts/fetch_fdma.py --index-only # 書誌だけ更新
```

マニュアルが改正されたら `scripts/fetch_fdma.py` の `FULL_TEXT_DOCS` にある URL・通知番号・
日付を差し替えて再実行してください。改正通知は
[通知・通達のページ](https://www.fdma.go.jp/laws/tutatsu/)の年別一覧から探せます。

```bash
python scripts/fetch_laws.py            # e-Gov から法令を再取得
python scripts/build_yoto.py            # 令別表第一から用途区分データを再生成
python scripts/validate_findings_map.py # 指摘辞書の参照先が実在するか検証

```

法令改正のあとはこの4行を実行して再デプロイします。アプリの「設定」タブに最終取得日が出るので、
古くなっていないか随時確認できます。

### 火災予防条例を入れる

例規集のページをブラウザで保存し、テキストに変換してからマスクします。

```bash
python scripts/ordinance_from_html.py 保存した例規集.html -o data/ordinances_src/xxx.txt
python scripts/anonymize_ordinance.py --names "〇〇市,〇〇県" --type "市"
```

`ordinance_from_html.py` は目次・附則・ページ末尾の索引を落として**本則だけ**を取り出します
（附則の経過措置も要る場合は `--whole`）。表はセルを全角スペースでつないで1行に残すので、
別表の離隔距離などもそのまま残ります。

`anonymize_ordinance.py` は自治体名・消防本部名・一部事務組合名・様式番号をマスクし、
`data/ordinances.json` を生成します。`市町村長` `都道府県知事` `市街地` `中核市` のような
一般的な法令用語は残します。実行後に表示される「**要確認候補**」を目視で確認し、
取りこぼしがあれば `--names` に足して再実行してください。候補がゼロになるまで繰り返すのが目安です。

**原文（`data/ordinances_src/`）はリポジトリに含めません。**
アプリには自治体名をマスクした状態のものだけが入ります。

> 収録済み：所属自治体の火災予防条例（本則89条）と同施行規則（本則14条）を
> `（自治体名非表示）火災予防条例` / `（自治体名非表示）火災予防条例施行規則` として取り込み済みです。
> **どの自治体の条例かはリポジトリに書きません。**書いてしまうとマスクした意味が無くなります。

題名はページの `<title>` から拾って `# 題名` の行として引き継ぎ、匿名化スクリプトが
マスクしたうえで使います。条例側の規則は、消防法施行規則と紛らわしくならないよう
**「条例規則」**というバッジで表示し、`条例規則2条` のように条番号でも引けます。

### データを更新したら

まず整合性を点検します。

```bash
python scripts/validate_data.py
```

指摘辞書・防火管理者判定・執行手続きの参照先条文が実在するか、防火管理者のルールが令別表第一を
漏れなく覆っているか、執行手続きの検索語がマニュアル本文にヒットするかをまとめて確認します。


`data/` を差し替えたときは **`sw.js` の `VERSION` を上げてください**。
上げないと、Service Worker のキャッシュが効いて利用者に古いJSONが一度表示されます。

### 指摘辞書を育てる

`data/findings_map.json` に指摘パターンを追記できます。追記したら必ず検証を実行してください。

```json
{
  "id": "任意のID",
  "label": "画面に出る指摘の名前",
  "category": "消防用設備等",
  "keywords": ["この語がクエリに含まれたら反応する", "..."],
  "refs": [{ "law_id": "336CO0000000037", "article": "第十条", "point": "設置基準" }],
  "ordinance": true,
  "note": "実務上の注意点"
}
```

## 公開する（スマホから使えるようにする）

スマートフォンのホーム画面から起動するには、GitHub Pages で公開する必要があります。
無料アカウントの場合、Pages を使うにはリポジトリを public にしてください。

```bash
gh repo edit --visibility public --accept-visibility-change-consequences
gh api -X POST repos/ancool2080-crypto/sasatsu-ai/pages -f "source[branch]=main" -f "source[path]=/"
```

数分後に `https://ancool2080-crypto.github.io/sasatsu-ai/` が開きます。
スマホのブラウザでアクセスし、共有メニューから「ホーム画面に追加」を選ぶとPWAとして起動します。
`manifest.json` の `start_url` と `scope` はリポジトリ名 `sasatsu-ai` を前提にしています。
別名にする場合は両方を書き換えてください。

## データの保存先

査察メモは既定でブラウザの localStorage にのみ保存されます。
PCとスマートフォンで同期したい場合は、設定タブから Firebase（Authentication + Firestore）を
設定してください。手順はアプリ内に表示されます。

Claude APIキーを登録した場合、キーは localStorage に平文で保存され、ブラウザから直接
Anthropic に送信されます。共用端末では登録しないでください。

### AI解説を使うときの守秘義務について

> **消防法第4条第4項**
> 消防職員は、第一項の規定により関係のある場所に立ち入つて検査又は質問を行つた場合に
> 知り得た関係者の秘密をみだりに他に漏らしてはならない。

このため、AI解説を押すと**送信前に全文を表示して確認を求めます**。入力文に自治体名・法人名・
建物名・電話番号・郵便番号らしき語が含まれていると警告を出します（`市町村長` `市街地` のような
法令用語は警告しません）。送信されるのは入力文・用途区分・条文抜粋だけで、**査察メモは送信されません**。

生成AIの業務利用が所属の情報セキュリティポリシーで認められているかは、利用者自身で確認してください。
APIキーを登録しなければ外部通信は一切発生せず、検索・条文表示・メモはすべてそのまま使えます。

### 査察メモの注意喚起

査察メモは端末の localStorage にしか無く、リポジトリには入りません。ただし**書き出し・印刷・
Firebase同期では端末の外に出る**ため、次の記述が含まれるメモには ⚠ の注意表示が出ます。

| 検知するもの | 例 |
|---|---|
| 実在の自治体名・法人名・建物名 | 市区町村名、法人格を含む名称、「〜ビル」「〜マンション」にあたる語 |
| 所属を指す語 | 「当本部」「当署」「本市」にあたる語 |
| 内部運用の呼称 | 「内規」「申し合わせ」「運用指針」「査察規程」にあたる語 |
| 人名らしき語・事案番号 | 「〜氏」「受理番号」「第N号事案」にあたる語 |
| 電話番号・郵便番号 | ハイフン区切りの番号、`〒` で始まる番号 |

**仮名（`A商店ビル` `甲ビル`）は警告しません** — 推奨している書き方だからです。
`市町村長` `市街地` `区域` のような法令用語も警告しません。

一覧の先頭に該当件数、各カードとメモ編集画面に検知語が出ます。書き出し時は確認ダイアログが挟まります。

### 公開前チェック

`public` にする前、および `data/findings_map.json` に追記したあとは、これを実行してください。

```bash
python scripts/check_publish_safety.py --names "自分の自治体名,都道府県名"
```

git 管理下のファイルを走査し、自治体名・所属固有の運用・人名・事案番号らしき記述を報告します
（e-Gov由来の `data/laws/` は国の公開データなので対象外）。
**どの自治体の条例を収録したかを README 等に書かないでください。**書くと条例をマスクした意味が消えます。

## 加工の明示

- e-Gov法令検索が提供する法令データを**条単位に分解して再構成**しています。
- 火災予防条例は自治体の例規集から取得し、**自治体を特定できる情報をマスクする加工**を行っています。
